## Backend and release evidence limits

Read-only service-role OpenAPI confirms deployed `triage_patient`, `submit_assessed_document`, `archive_specialist_patient`, `get_daily_token_usage`, assessment linkage and queue allocation columns. It does not prove policy bodies, authenticated grants, migration replay, deployed Edge code, or runtime authorization. No application rows were read and no production writes/deployments occurred.

The checked-out web configuration's public API key returned HTTP 401 `Invalid API key`; this is evidence about local configuration, not proof of the production web/mobile configuration. Function inventory is blocked by the CLI's `Access token not provided` result. There is no inspected mobile release artifact or configured mobile production target, so shipped behavior remains unknown.
